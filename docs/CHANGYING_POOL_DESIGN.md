# 长盈选股标的池设计方案（V591）

## 目标

每天凌晨系统空闲时，用 TDX 在线数据对全市场做一次排序检索，把「长盈标的池」
（默认 20 只）沉淀到本地。前端选股页直接读本地池，避免白天反复打 TDX、减少压力。
市值低于 100 亿的标的直接排除。

## 一、硬性门槛（先排除，再打分）

1. 总市值 >= 100 亿元（总市值 = 总股本 total_shares × 目标日收盘价）。
2. 净利润 > 0（亏损股不进长盈池）。
3. 有「截至目标日已披露」的财报（point-in-time，无未来函数）。
4. 财报披露日 <= 目标日（沿用 indicators.pick_report 规则）。

可选（后续再加）：剔除 ST、上市不满 60 日次新股、停牌股。

## 二、财务指标框架（树粮菜三维，各 0-100 分）

沿用 screener.py 的打分，作为「挑 20 只」的依据。每只股票同时算三张明细，
取最高分类作为结论。

### 树型（核心底仓）
- 盈利为正：10 分
- 营收体量年化 >= 100 亿：10 分
- 年化 ROE：30 分（>=20 满分，15-20 给 24，10-15 给 15，<10 给 4）
- 增长（营收/净利同比各自为正，各 15）：30 分
- 毛利率：20 分（>=40 满分，25-40 给 14，<25 给 5）

### 粮型（稳健收益）
- 净利润为正：20 分
- 净利同比未大幅下滑（>= -10%）：15 分
- 资产负债率：25 分（<=40 满分，40-60 给 17，60-75 给 8，>75 给 2）
- 每股经营现金流为正：20 分
- 每股收益（年化）为正：20 分

### 菜型（波段收益）
- 营收同比：35 分（>=20 满分，10-20 给 22，0-10 给 10）
- 净利同比：35 分（>=30 满分，10-30 给 20，0-10 给 5）
- 净利率：20 分（盈利且净利率>0 满分，盈利但未披露/极低给 10）
- 每股经营现金流为正：10 分

## 三、排序与挑选 20 只

1. 过滤后按「分类得分」降序。
2. 同分按「三维总分」降序（多维度都强的排前）。
3. 取前 20 只。
4. 输出分类分布（tree/grain/vegetable 各多少），前端可展示。

## 四、凌晨沉淀管线（refresh）

1. 拉取 TDX gpcw 财报文件列表（available_report_zips）。
2. 全市场 point-in-time 指标加载（load_all_periods_frame + pick_reports_bulk）。
3. 树粮菜打分，先取 top_n（默认 200）候选。
4. 对候选逐只取目标日收盘价（TDX 日线，QFQ 前复权口径与图表一致）。
5. 计算总市值 = total_shares × 收盘价，剔除 < 100 亿。
6. 重新排序取前 20，连同评分明细、市值、报告期、数据源写入本地 SQLite。

## 五、本地沉淀存储

- 文件：~/.easy_tdx/changying_pool.db（受 EASY_TDX_CONFIG_DIR 覆盖）。
- 表：changying_pool(updated_at, trade_date, symbol, market, code, category,
  score, total_mcap_yi, close, report_date, data_source, scores_json,
  details_json, indicators_json)。
- 每次 refresh 全量替换，保留 updated_at，前端展示「数据更新于 X」。

## 六、调度与读取

- CLI：easy-tdx changying-refresh（手动或 cron 0 0 * * * 调用）。
- Web：easy-tdx serve 增加 --changying-scheduler 开关，默认开启；后台线程
  每天 00:00 跑一次 refresh，失败仅告警不影响服务。
- 读取：POST /api/v1/stock-pick/screen 优先读本地池（source=local），本地为空
  或过期（> 24h）时回退在线扫描（source=online）。

## 七、验收标准

- 市值 < 100 亿的标的绝不出现在长盈池。
- refresh 后可离线读取 20 只标的及完整评分明细。
- 前端选股页白天读取本地池，不打 TDX 财报/行情。
- CLI/cron 与 Web 定时器两条路径均可用。
