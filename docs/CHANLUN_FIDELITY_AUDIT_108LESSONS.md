## 一、原文定义提炼（审计基准）

| 概念 | 原文定义 | 出处 |
|---|---|---|
| **顶分型** | 第二K线高点是相邻三K线高点中**最高的**，而低点**也是**相邻三K线低点中**最高的** | 62课 line 16 |
| **底分型** | 第二K线低点是相邻三K线低点中**最低的**，而高点**也是**相邻三K线高点中**最低的** | 62课 line 16 |
| **笔** | 两个**相邻的**顶和底之间构成一笔；顶底之间**必须至少有一根K线**（图5是最基本图形）；顶底**共用K线违反结合律，不算一笔**（图3） | 62课 line 20 |
| **包含关系（合并方向）** | 向上时取两K线最高点为高点、低点中的较高者为低点；向下时反之。**向上判定：`gn>=gn-1`**；向下判定：`dn<=dn-1` | 62课 line 22、65课 line 8/14 |
| **包含关系（顺序原则）** | 先用第1、2根确认新K线，再用新K线去比第3根——**不符合传递律**，必须顺序处理 | 65课 line 10 |
| **中枢** | 某级别走势类型中，被**至少三个连续次级别走势类型**所**重叠**的部分。对最低不可分解级别，定义为至少三个该级别单位K线重叠部分 | 17课 line 20 |
| **ZG/ZD** | `ZG=min(g1、g2)`，`ZD=max(d1、d2)`，其中 g1/d1、g2/d2 是**与中枢形成方向一致的两个Z走势段（A段、C段）**，中间反向笔（B段）不参与；原文没有 g3 | 20课 line 22-23 |
| **GG/DD** | `GG=max(gn)`、`DD=min(dn)`，**n遍历中枢中所有 Zn**（Z走势段，即与中枢形成方向一致的段） | 20课 line 22 |
| **中枢延伸** | 等价于**任意区间 `[dn,gn]` 与 `[ZD,ZG]` 有重叠**（无比例阈值） | 20课 line 24 |
| **中枢结束** | 出现 `Zn` 使 `dn>ZG` 或 `gn<ZD` ⇒ 产生高级别中枢或趋势及延续 | 20课 line 24 |
| **线段** | 至少三笔；特征序列 = 与线段方向**相反**的笔；需做包含处理；向上线段只考察顶分型、向下线段只考察底分型；缺口（相邻特征元素无重叠）分情况处理 | 65课 line 28-36、67课 line 28-50 |

## 二、偏差清单（按严重程度排序）

### 偏差 1【高】中枢 GG/DD 把反向笔（B段）也算进 Zn，违反第20课「n遍历中枢中所有Zn」

- **原文定义**：第20课 line 22 逐字：「为方便起见，以后都把这些与中枢方向一致的次级别走势类型称为`Z走势段`，按中枢中的时间顺序，分别记为`Zn`等，而相应的高、低点分别记为`gn`、`dn`，定义四个指标，`GG=max(gn)`，`G=min(gn)`，`D=max(dn)`，`DD=min(dn)`，**n遍历中枢中所有Zn**。」
  ⇒ GG/DD 只统计**与中枢形成方向一致**的段（回升中枢只算向上笔，回调中枢只算向下笔）。
- **代码实现**：`zs.py:334-335`
  ```python
  gg_candidate = max(gg_candidate, bi.high)
  dd_candidate = min(dd_candidate, bi.low)
  ```
  对**每一根**加入候选的笔（含方向相反的第2、4、6…笔）都更新 gg/dd，无方向过滤。
- **偏差**：反向笔的极值被计入 GG/DD。当反向笔极值超出同向笔时（如 B 段高点高于 A 段高点，即「起点极值被趋势穿越」），GG 被系统性抬高。
- **实测证据**（`/tmp/audit_round10.py` J1b）：构造 `A up[10,20]`、`B down[25,3]`、`C up[3,18]`、`D down[18,9]`：
  - 原文口径（只算 Z走势段 A、C）：`GG = max(20,18) = 20`
  - 代码实测输出：`gg = 25`（把 B 段的 25 算进去了）
  - ⇒ GG 虚高 25%，进而影响 `mark_upgraded_zss`（`zs.py:199-201` 的定理二判定用 `cur.gg/prev.dd`）和背驰比较。
- **影响面**：所有中枢的 `gg`/`dd` 字段、第20课定理二升级标记、背驰力度比较。
- **严重程度**：**高**（直接改变中枢极值定义，且误差方向是单向放大 GG）。

### 偏差 2【高】analyser 把笔的 high/low 改成「笔区间内所有原始K线极值」，破坏第20课 gn/dn = 笔端点定义

- **原文定义**：第20课 line 22-23 的 `gn`/`dn` 是 Z走势段（笔）的高/低点。第62课 line 18：「顶分型的最高点叫该分型的顶……当我们以后说顶和底时，就分别是说顶分型的顶和底分型的底。」⇒ **笔的高/低点就是其两个端点分型的顶/底值**，笔中间的波动「都可以忽略不算」（62课 line 20）。
- **代码实现**：`analyser.py:830-837`
  ```python
  for bi in bis:
      si = bi.start.bar_index
      ei = bi.end.bar_index
      if 0 <= si <= ei < len(klines):
          seg = klines[si : ei + 1]
          if seg:
              bi.high = max(k.high for k in seg)
              bi.low = min(k.low for k in seg)
  ```
- **偏差**：用 `[start.bar_index, end.bar_index]` 区间内**所有原始K线**的极值覆盖 `bi.high/low`，使笔极值可以**超出端点分型值**。而 `find_zss`（`zs.py:314-315, 334-335`）和 `zs.py:87-88` 的中枢延伸判定用的正是 `bi.high/bi.low`。
- **实测证据**：
  - `/tmp/audit_round4.py` E3：600519日线 `bi2` 端点 `start=1382.35 / end=1496.85`，但 `bi.high=1500.32`（**超端点 3.47 元**）；000001日线 `bi11` 端点 `11.62`，`bi.high=11.93`。
  - `/tmp/audit_round9.py` 全量 5 fixture：**51 根笔中 6 根 high 超端点、2 根 low 破端点（11.8%）**。
  - `/tmp/audit_round10.py` J4：把 `b0.high` 从 20 改为 22 后，中枢 `gg` 从 20 变为 22。
- **连带影响**：
  1. `zs.py:314-315` 的中枢延伸判定用 `bi.high/bi.low` 与 `[ZD,ZG]` 比重叠 ⇒ 笔区间变宽 ⇒ **延伸判定偏宽松**（更多笔被判为「仍在中枢内延伸」，中枢被拉长）。
  2. 叠加偏差 1，GG 被双重放大。
- **严重程度**：**高**（这是生产管道（`process_klines`）的必经步骤，不是可选开关；直接影响中枢区间与延伸）。

### 偏差 3【中】分型判定在 `fx_strict=True`（默认）下用严格 `>`，会丢弃「并列极值」分型

- **原文定义**：第62课 line 16：「第二K线高点是相邻三K线高点中**最高的**」——原文只要求「最高」，**未排除并列**。三根K线并列最高时，第二根仍是「最高的」之一。
- **代码实现**：`fractal.py:61-73`（`fx_strict=True` 分支，`config.py:140` 默认 `True`）
  ```python
  is_ding = (mid.high > left.high and mid.high > right.high
             and mid.low  > left.low  and mid.low  > right.low)
  ```
- **偏差**：并列最高（`mid.high == left.high`）时不成立 ⇒ 顶分型被漏判。
- **实测证据**（`/tmp/audit_round11.py` K2）：直接给 `find_fractals` 传未合并 CLKline `[8,12] / [10,12] / [9,11]`：
  - `fx_strict=True` → `[]`（漏判）
  - `fx_strict=False` → `[('ding', 12)]`（正确）
  - 原文应判为顶分型。
- **重要限定（实测结论，非推测）**：`/tmp/audit_round8.py` I8 数学证明 + `/tmp/audit_round9.py` D9 实测——经过 `merge_klines` 后，任意两根缠论K线若 `high` 相等则必有包含关系，因此**生产路径上不存在相邻并列极值**（5 个 fixture 上 strict 与非 strict 分型数**完全相同，差=0**）。
  ⇒ 该偏差**只在直接调用 `find_fractals` 且传入未合并数据时**才可观测。
- **严重程度**：**中**（默认配置下无实际影响，但 `find_fractals` 是公开 API，且注释「严格模式下不允许相等」与原文「最高」不等价——属于把原文未有的约束写成默认行为）。

### 偏差 9【低】`kline_merge.py:74/78` 的合并方向判定与65课 `gn>=gn-1` 不一致 ✅ 已修（V860）

> **状态更新（2026-10-17）**：`kline_merge.py:74` 已从严格 `>` 改为 `>=`（符合第65课
> line14「gn>=gn-1」含等号）。真实数据发生率实测 0.00%（14400 根 K 线 0 次命中），
> 但按原文修正消除理论偏差。

- **原文定义**：第65课 line 14：「假设，第n根K线满足第n根与第n+1根的包含关系，而第n根与第n-1根不是包含关系，那么如果`gn>=gn-1`，那么称第n-1、n、n+1根K线是**向上的**；如果`dn<=dn-1`，那么称第n-1、n、n+1根K线是**向下的**。」
- **代码实现**：`kline_merge.py:73-78`
  ```python
  if len(result) >= 2:
      direction = "up" if prev.high > result[-2].high else "down"
  else:
      # 只有第一根，根据前一根 K 线本身的阴阳判断方向
      direction = "up" if prev.close >= prev.open else "down"
  ```
- **偏差**：
  1. 用**严格 `>`** 而非原文的 `>=`（等号时落到 `down`，原文应判 `up`）；
  2. 只有一根缠论K线时，**用K线阴阳（close vs open）判定方向**——原文65课的向上/向下定义需要三根K线（n-1, n, n+1），首根无 `n-1`，**原文对此无定义**，代码的阴阳回退是原文之外的工程规则。
- **实测证据**：

## 四、重点问题的直接回答（任务书 §3）

**Q1：分型判断是否检查「高点最高且低点也最高」双维度？**
- **K线分型：是**。`fractal.py:61-86` 两个分支都检查 4 个条件（`mid.high` vs 两侧 high + `mid.low` vs 两侧 low），注释也明确写了62课依据。✅
- **线段特征序列分型：否**。`xd.py:96-100` 只查 `mid[1]`（high）或 `mid[2]`（low）单一维度，**未查第二维度**。❌ 见偏差 4，有可复现反例。
- `fx_strict` 的 `>` vs `>=` 之别只在未合并数据上可观测（生产路径差=0），见偏差 3。

**Q2：包含关系合并方向是否按65课 `gn>=gn-1` 判断？**
- **逻辑结构对，运算符错**：`kline_merge.py:74` 用 `prev.high > result[-2].high`（严格大于），原文是 `gn>=gn-1`。
- **但实测证明等号分支数学上不可达**（I8：两根无包含K线若 high 相等则必有包含），因此**无实际误差**。
- **真正的不一致**：① 首根缠论K线用「K线阴阳」定方向（原文无此规则，`kline_merge.py:78`）；② 同一规则在 `xd.py:72` 的 else 默认 `up`（与65课等号口径一致），在 `kline_merge.py:78` 的 else 走阴阳（不一致）。见偏差 9。

**Q3：笔是否要求顶底间至少1根独立K线？是否允许共用K线？**
- **默认口径（`bi_type="new"`）：是，且更严**。实测 `gap>=3 ⇔ 独立K线数>=2`，即要求**至少2根**独立K线（原文只要求1根）。不违反原文，但 `bi.py:69-71/86` 注释写「至少1根」是错的。见偏差 7。
- **共用K线：默认拒绝**。实测 51 根笔中 0 根共用中间K线；`_can_form_bi` 对 `gap=2`（独立0根）返回 False。✅

**Q4：中枢是否真的「三段重叠」？**
- **ZG/ZD：是，严格按第20课**。`zs.py:326-330` 用 `candidate_lines[0]` 与 `candidate_lines[2]`（A段、C段）算 `min(high)/max(low)`，B段不参与；实测 3/3 中枢与 `[lines0∩lines2]` 完全一致。✅
- **段数下限：是**。`zs_min_lines=3`，实测 2 笔返回 `[]`。✅
- **连续性：是**。实测 0/10 中枢由非连续笔构成。✅
- **GG/DD：否**。`zs.py:334-335` 把**所有**笔（含反向B/D/F…段）计入 gg/dd，违反第20课「n遍历中枢中所有Zn」。❌ 见偏差 1，有可复现反例（gg=25 vs 原文 20）。
- **延伸判定：口径对但输入被污染**。`zs.py:314-315` 用 `bi.high/bi.low` 与 `[ZD,ZG]` 比重叠，符合定理一；但 `bi.high/low` 已被 `analyser.py:830-837` 扩成区间内原始K线极值（11.8% 的笔超端点），使重叠判定偏宽松。❌ 见偏差 2。
