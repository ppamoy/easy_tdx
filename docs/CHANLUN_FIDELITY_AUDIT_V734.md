## 4. ❌ 1买/1卖：实际是"笔背驰"，不是原文的"趋势背驰"（未改，需先回测）

### 问题
`_is_strong_beichi` 有两条分支：
1. **笔背驰**：相邻同向笔力度衰竭 —— **不要求任何中枢**
2. **趋势背驰**：两个同向中枢之间离开段力度衰减 —— 原文对 1买 的要求

分支 1 先跑且命中即 `return True`，所以**零中枢/单中枢也能出 1买**。
而代码自己的注释写着：「一买/一卖 只认趋势背驰……不把盘整背驰算作一买」。

### 实测：趋势背驰分支**从不触发**
给 `_is_strong_beichi` 加计数器（8 只日线，446 次调用）：

| 分支 | 命中 |
|---|---|
| 笔背驰 | 107 |
| **趋势背驰** | **0** |

逐门槛定位（下跌方向，128 个中枢对）：

| 门槛 | 通过 | 卡住 |
|---|---|---|
| 相邻同向下跌中枢 | 65 | 63 非同向 |
| 离开段存在 | 62 | 3 未完成 |
| **离开段方向 = down** | **1** | **61 方向不符** |
| 创新低 | 0 | 1 |

⇒ **卡点：61/62 的"离开段"方向不是 down。**
代码取 `zs.lines[-1].index + 1`（中枢末笔的**下一笔**）当离开段。

**已用独立探针坐实（6 只日线 / 96 个中枢）**：

| 中枢末笔方向 → 其后一笔方向 | 计数 |
|---|---|
| down → up | 57 |
| up → down | 39 |
| **同向（= 真离开段）** | **0 / 96 = 0%** |
| **反向（= 先回抽）** | **96 / 96 = 100%** |

**中枢末笔之后的一笔 100% 是反向回抽，从来不是离开段。**
所以 `curr_exit.direction != direction` 这一关**恒真** ⇒
趋势背驰分支**在任何真实数据上都不可能触发**，不是"阈值太严"，
是**离开段定位系统性错位一格**（应再往后取一笔，或按"离开 ZG/ZD 区间"判定）。

V730 的注释写着「修正为取离开段 bis[lines[-1].index + 1]」，
**这个修正本身是错的** —— 它把"回抽笔"当成了"离开段"。

### 扣成本收益对照（20 只日线，`scripts/audit_chanlun_beichi_pnl.py`）

用 `ChanlunPairStrategy` + 往返成本约 0.56%：

| 口径 | 配对笔数 | 胜率 | **每笔扣成本均收益** | 1buy 笔数 |
|---|---|---|---|---|
| 当前（笔背驰） | 177 | 48.02% | +2.728% | 87 |
| **原文（只趋势背驰）** | **67** | **41.79%** | **+7.063%** | **0** |

三个都必须同时看到的点：
1. **改了以后 1买 彻底消失**（笔数 NaN）—— 与"趋势背驰分支从不触发"完全一致。
2. **每笔收益翻了 2.59 倍**（+2.73% → +7.06%），但**胜率反而降了**

⇒ **结论：改成纯趋势背驰，在 20 只样本上收益基本持平（略降），同时丢掉 62% 的
交易机会和整个 1买 信号族。** 没有理由为了"更符合原文"付出这个代价。

⚠️ 口径限制：上表是**同权每笔平均**，不是账户实际总收益（未考虑资金占用、
持仓重叠、复利）。20 只样本、67 笔也偏小，**不宜据此下强结论**。

## 6. ⚠️ 方法教训（我自己踩的，别重蹈）

1. **别用"写源文件"做 A/B。** 第一版脚本直接 `MMD.write_text(patched)`，
   被 `job_kill` 中断后**源码留在 patched 状态**（`total_time > 1000000000`），
   我 `git checkout` 了两次才恢复。现改为 `exec` + 注册 `sys.modules`。

2. **字符串替换式 A/B 必须先断言锚点命中数。** 第一版只替换了
   「带注释的买侧那行」，卖侧那行没有注释、锚点不匹配 ⇒
   得出「卖侧 0% 被砍」的**假结论**。修正后卖侧实为 44%。
   同理，`for j in range(bi_idx-1,-1,-1):` 在文件里有 2 处，
   必须按行号定位，否则会误改 `_get_beichi_strength`。

3. **A/B 不能靠 `ChanlunAnalyser.process_klines` 跑。**
   我 exec 出一份改过的 `mmd` 模块，然后调 `process_klines` 期待它用我的版本
   —— 但它内部 `from easy_tdx.chanlun.mmd import ...` 拿的是**已安装**的模块，
   我的副本根本没参与 ⇒ 两组跑的是同一份代码，得出「A 与 C 完全一致、
   差 0」的**假结论**（总数巧合相同更是加强了错觉）。
   **必须直接调被 patch 的模块函数**（`mod._find_second_type_mmds(...)`），
   或 patch 符号 `A.find_mmds_v44`。
   这次是靠"逐只对比"才发现的：总数差 0，但 8 只里 6 只有差异、且方向一致。
   ⇒ **总数相同不等于等价，必须逐样本比。**
