## Context

easy_tdx 后端测试体系已达到工业级（2609 passed，质量门禁全绿），但前端测试、策略/路由覆盖均衡性、核心算法模块内聚度、CI 门禁完整度四个方面明显落后。本设计给出这四个能力域的落地方案与关键决策。

当前架构概览：

  src/easy_tdx
    chanlun/           缠论算法（mmd.py 约 2.96 万行，是绝对核心）
    backtest/          回测引擎 + 27 个注册策略
    web/routers/       21 个 FastAPI 路由模块
    cli/               click 命令组（在线/离线双链路）
  web-ui/src
    components/        31 个 Vue 组件（V102DecisionCard 等）
    views/             13 个视图页
    grading/           评级纯函数（唯一有测试的目录）
  tests/unit           125 个测试文件（策略/路由覆盖严重不均）

## Goals / Non-Goals

**Goals:**
- 建立前端自动化测试闭环：vitest + @vue/test-utils，覆盖纯函数、stores、关键组件与视图的冒烟渲染。
- 消灭后端「零覆盖」策略与「零覆盖」路由，把覆盖率门槛提升到 65 并保持全绿。
- 拆分 mmd.py，清理无生产调用点的版本化死函数，形成清晰的子模块边界。
- 前端 lint/format 与测试进 CI，覆盖率产出报告，仓库根目录去噪。

**Non-Goals:**
- 不引入 E2E 浏览器测试框架（Playwright/Cypress）——组件级与纯函数级足够覆盖当前风险面，E2E 留待后续。
- 不重写缠论算法、不改变任何信号/置信度/买卖点语义。
- 不新增机器学习、实盘交易等功能特性——本变更只做质量工程。
- 不强行把覆盖率提到 80+；65 是可持续的近期目标，70 是中期方向。

## Decisions

D1 前端测试框架选 vitest 而非继续用 node:test。理由：与 Vite 原生集成、支持 .vue 单文件组件、快照与 watch 模式成熟，grading 现有 node:test 用例可低成本迁移到 vitest 统一入口。

D2 组件测试采用「纯逻辑优先 + 关键组件冒烟 + 视图路由渲染」三层策略。优先级：V102DecisionCard > 各视图页 > 通用组件。不为 31 个组件平均用力，聚焦用户可感知的决策卡片与数据展示链路。

D3 策略补测采用「参数校验 + 信号产生 + 空数据/短数据边界 + 参数化遍历」模板。15 个零覆盖策略大多是同构的 ParametrizedStrategy，用一张参数化表即可高效覆盖，而不是为每个策略手写冗长用例。

D4 路由补测采用契约测试而非行为测试：断言响应模型字段、错误分支（无数据/非法参数）与 DataFrameResponse 序列化，不追求覆盖真实行情服务的完整数据路径。真实行情链路继续由 integration 测试负责。

D5 mmd.py 拆分采用「按职责纵向切分 + 惰性再导出」策略。优先把体积大且边界清晰的指标计算簇（约 200+ 个 _calc_* 函数）抽出为 mmd/ 子包，顶层保留 find_mmds 与核心类型以兼容现有导入，避免一次性重写导致大面积回归。

D6 死代码清理采用「先审计引用、再标记弃用、最后删除」三步法。对 find_mmds_v39/v40/v41/v42/v76 等版本化函数，先证明无生产调用点（本次审计已发现 v40/v41/v76 无生产调用），有外部引用风险的保留 deprecation 别名一个版本周期，其余直接删除并用全量回归守护。

D7 覆盖率门槛 60 → 65。理由：当前约 61%，补齐零覆盖策略与路由后保守估计可到 65-68；一次性定 70 会让 CI 长期红灯并鼓励「为覆盖率写测试」的反模式。65 是诚实且可执行的近期门槛。

D8 前端 lint 采用 eslint + vue-eslint-parser + prettier，沿用后端 ruff 的「先 format 后 check」门禁顺序；不引入过度严格的规则集，先落地最基础的 recommended 级。

## Risks / Trade-offs

- god-module 拆分是最高风险项：即使纯搬移也可能因循环导入、mypy strict、E501 豁免边界改变而破坏门禁。缓解：拆分时每个 commit 只移动一个逻辑簇并立即全量回归，顶层保留再导出 shim 保兼容。
- 15 个零覆盖策略补测可能暴露出既有策略的真实 bug，导致范围扩张。缓解：本变更只补「测试钉住现状」，发现的 bug 单独开 issue/后续版本处理，不在本变更内顺手大改策略逻辑。
- 前端引入 vitest/eslint 会新增约十余个 devDependencies，锁文件与 node_modules 体积上升。缓解：全部放 devDependencies，生产 build 不受影响。
- 覆盖率 65 门槛首次启用时，不同 Python 版本的 CI 矩阵可能因 import 路径差异出现微小波动。缓解：保持现有 fail_under 的容差，先跑通再微调。
